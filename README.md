# Управление зависимостями в PHP с использованием Composer
---

## 1. Введение

**Composer** — это стандартный менеджер зависимостей в экосистеме PHP. В отличие от системных пакетных менеджеров (например, `apt` или `yum`), Composer управляет зависимостями **попроектно**, загружая необходимые сторонние библиотеки в локальную директорию `vendor/` проекта и генерируя централизованный автозагрузчик классов по стандартам **PSR-4 / PSR-0**.

В данном проекте сформирован набор из **9 зависимостей**, решающих функциональные требования технического задания.

## 3. Разделение зависимостей


1. **`require` (Runtime-зависимости):**
   Это код, который непосредственно исполняется при работе приложения пользователем (ORM, PDF-генератор, почтовый клиент). Без этих библиотек сервис выдаст фатальную ошибку (`Class not found`).
2. **`require-dev` (Development-зависимости):**
   Это вспомогательный инструментарий программиста: фреймворки тестирования (PHPUnit), статические анализаторы (PHPStan, Psalm), линтеры стилей кода (PHP-CS-Fixer).
   
   **Почему PHPUnit вынесен в `require-dev`:**
   * **Безопасность:** Тестовые библиотеки часто содержат отладочные скрипты, фикстуры и средства запуска кода, которые при попадании на боевой сервер могут стать вектором для удаленного выполнения кода (RCE).
   * **Размер и ресурсы:** Установка PHPUnit тянет за собой десятки подпакетов (генераторы моков, анализаторы AST). На production-сервере они выполняют роль «мертвого груза». При деплое всегда используется флаг `--no-dev`:
     ```bash
     composer install --no-dev --optimize-autoloader
     ```

## 4. `composer.json` и `composer.lock` 

* **`composer.json`** — объявляет ограничения версий (например, `^11.0`, что означает любую версию от `11.0.0` до `<12.0.0`).
* **`composer.lock`** — фиксирует **точный хэш коммита и точную версию** каждого установленного пакета и всех его транзитивных зависимостей на момент выполнения `composer install / composer update`.

## 5. Автозагрузка по стандарту PSR-4

В блоке `autoload` файла `composer.json` настроено правило:
```json
"autoload": {
    "psr-4": {
        "App\\": "src/"
    }
}
```
Это означает, что класс с пространством имен `App\DemoService` автоматически связывается с файлом `src/DemoService.php`. Composer генерирует оптимизированную карту классов в `vendor/autoload.php`. В приложении достаточно один раз написать:
```php
require_once __DIR__ . '/vendor/autoload.php';
```
после чего любые сторонние библиотеки и классы проекта загружаются по требованию на лету.
